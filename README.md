# 차곡 — 나만 쓰는 가계부 (GitHub 전용)

평소에는 **PIN 숫자 4자리**로 여는 나만의 가계부입니다. 다른 서비스 없이 **GitHub만** 씁니다. 어느 노트북이나 데스크톱에서 열어도 같은 기록이 보입니다. 화면 디자인, 메뉴, 계산 방식은 기존 차곡과 같습니다.

## 구조

| 저장소 | 공개 여부 | 들어 있는 것 |
| --- | --- | --- |
| 사이트 저장소 (예: `chagog`) | Public | 화면 코드, 비밀번호로 잠긴 설정(`config.js`) |
| 기록 저장소 (예: `chagog-data`) | **Private** | 암호화된 가계부 파일 하나(`ledger.enc.json`) |

- 가계부 기록은 **내 브라우저에서 비밀번호로 암호화된 뒤** 비공개 기록 저장소에 저장됩니다. GitHub에도 암호화된 상태로만 올라갑니다.
- 사이트 주소를 누가 알아내도 **잠금 화면만** 보입니다. 비밀번호가 없으면 기록 저장소에 접근할 열쇠(토큰)도, 기록을 풀 열쇠도 꺼낼 수 없습니다.
- **긴 비밀번호와 PIN 4자리를 함께 씁니다.** 긴 비밀번호는 새 기기를 처음 등록할 때 한 번만 쓰고, 그 기기에서는 이후 PIN 4자리로 엽니다. PIN은 기기마다 따로 정하며, 그 기기 안에만 저장됩니다.
- 사이트 저장소를 Public으로 두는 이유는 무료 GitHub Pages가 공개 저장소에서만 동작하기 때문입니다. 그 안에 기록은 없습니다.

## 처음 만드는 순서

### 1. 기존 기록 백업
지금 쓰던 가계부에서 왼쪽 **↓ 데이터 백업**으로 JSON 파일을 받아 둡니다.

### 2. 기록 저장소 만들기 (Private)
GitHub에 로그인 → 오른쪽 위 **+** → **New repository**
- Repository name: `chagog-data`
- **Private** 선택
- **Create repository**

### 3. 토큰 만들기 (기록 저장소 전용 열쇠)
GitHub 오른쪽 위 프로필 → **Settings** → 맨 아래 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
- Token name: `chagog`
- Expiration: 원하는 기간(만료되면 7단계처럼 새 토큰으로 바꾸면 됩니다)
- Repository access: **Only select repositories** → `chagog-data` 하나만 선택
- Permissions → Repository permissions → **Contents: Read and write**
- **Generate token** → 나온 토큰(`github_pat_…`)을 복사해 둡니다. 이 화면을 닫으면 다시 볼 수 없습니다.

### 4. 사이트 저장소 만들고 Pages 켜기
1. **New repository** → 이름 `chagog` → **Public** → **Create repository**
2. **uploading an existing file** 링크(또는 Add file → Upload files)를 누르고, 압축을 푼 `chagog-ledger` 폴더 **안의** 파일과 폴더를 모두 끌어다 놓은 뒤 **Commit changes**
3. **Settings → Pages** → Source: **Deploy from a branch**, Branch: **main / (root)** → Save
4. 1~2분 뒤 같은 화면에 주소가 나옵니다. 예: `https://아이디.github.io/chagog/`

### 5. 설정 만들기
1. `https://아이디.github.io/chagog/setup.html` 을 엽니다.
2. **처음 설정**에 GitHub 아이디, 기록 저장소 이름(`chagog-data`), 3단계 토큰, 가계부 비밀번호를 넣고 **확인하고 설정 만들기**를 누릅니다. 저장소가 Private인지, 토큰이 맞는지 자동으로 확인합니다.
3. 나온 내용을 **복사하기** → 사이트 저장소에서 `config.js` 열기 → 연필(✏️) → 원래 내용을 **전부 지우고** 붙여넣기 → **Commit changes**

### 6. 이 기기 등록하고 기록 불러오기
1~2분 뒤 가계부 주소를 엽니다. 처음 여는 기기에서는 **긴 비밀번호**와 이 기기에서 쓸 **PIN 4자리**를 넣고 **이 기기 등록하고 열기**를 누릅니다. "새 가계부" 상태로 열리면 왼쪽 **↑ 데이터 불러오기**로 1단계 JSON을 넣습니다.

다음부터 이 기기에서는 PIN 4자리만 누르면 열립니다. 다른 노트북·데스크톱에서는 같은 주소를 열고 같은 방식으로 한 번 등록하면, 그 뒤로는 그 기기에서도 PIN으로 열리고 같은 기록이 보입니다.

## 나중에 할 일

### 7. 토큰이 만료됐거나 긴 비밀번호를 바꾸고 싶을 때
`setup.html` → **토큰·긴 비밀번호 변경** → 현재 긴 비밀번호와 새 토큰/새 긴 비밀번호를 넣고 → 나온 내용으로 `config.js`를 다시 바꿉니다. 기록은 그대로 열립니다.
- 긴 비밀번호만 바꿨다면: 이미 등록된 기기는 PIN 그대로 열립니다.
- 토큰을 바꿨다면: 각 기기가 처음 열 때 "토큰 만료" 안내와 함께 등록이 지워지고, 긴 비밀번호로 한 번 다시 등록하면 됩니다.

### 8. PIN을 바꾸거나 잊었을 때
잠금 화면의 **PIN을 잊었어요 · 이 기기 등록 다시 하기**를 누르고, 긴 비밀번호로 다시 등록하면서 새 PIN을 정합니다. 기록은 지워지지 않습니다.

## 꼭 알아 둘 점
- **PIN을 5번 틀리면** 그 기기의 등록이 지워집니다. 기록은 그대로이고, 긴 비밀번호로 다시 등록하면 됩니다.
- PIN 4자리는 **이미 등록한 내 기기**를 지키는 용도입니다. 노트북 자체의 로그인 잠금도 켜 두세요. 공용 PC나 남의 기기에서는 등록하지 마세요(쓴 뒤에는 **PIN을 잊었어요 · 이 기기 등록 다시 하기**로 등록을 지우세요).
- 브라우저의 사이트 데이터를 지우거나 시크릿 창을 쓰면 등록이 사라집니다. 긴 비밀번호로 다시 등록하면 됩니다.
- **긴 비밀번호를 잊으면 기록을 되살릴 방법이 없습니다.** 저도, GitHub도 풀 수 없습니다. 가끔 **↓ 데이터 백업**을 받아 안전한 곳에 보관하세요.
- **긴 비밀번호는 정말 길게** 정하세요(10자 이상, 짧은 문장형 추천). 잠긴 설정 파일이 공개 저장소에 있어서, 누군가 그 파일을 받아 무작위로 맞춰 보는 시도를 할 수 있기 때문입니다. 이 자리에 4자리 숫자를 쓰면 몇 시간 안에 풀릴 수 있어서, 4자리는 기기 안에서만 쓰도록 나눠 두었습니다.
- 토큰이나 비밀번호를 `config.js`나 다른 파일에 **직접 적어 올리지 마세요.** 반드시 `setup.html`이 만들어 준 잠긴 내용만 넣습니다.
- 새로고침하거나 창을 닫으면 다시 PIN을 물어봅니다. 30분 동안 아무것도 안 하면 자동으로 잠깁니다.
- 두 기기에서 동시에 열어 두면 15초마다 서로의 변경을 확인합니다. 서로 다른 항목을 고쳤으면 자동으로 합치고, 같은 칸을 다르게 고쳤으면 덮어쓰지 않고 멈춥니다.
- 저장할 때마다 기록 저장소에 커밋이 하나씩 쌓입니다(암호화된 상태). 그만큼 이전 버전이 남는 셈이라 기록 보호에도 도움이 됩니다.

## 2026년 11월 업데이트: 기간 직접 지정 · 계좌 간 예산 이체 · 글자 확대

### 가계부 월간 기간
- 기본은 한국 달력 기준으로 **매월 21일 시작**입니다. 21일이 토요일 또는 일요일이라면 **직전 금요일부터** 시작합니다. 예: 2026-11-21(토) → 2026-11-20(금), 2027-02-21(일) → 2027-02-19(금).
- 각 기간의 **종료일은 다음 기간 시작일의 전날**이며, 시작일·종료일 모두 집계에 포함됩니다. 따라서 2026년 10월 가계부 기본 기간은 **2026-10-21 ~ 2026-11-19**, 11월은 **2026-11-20 ~ 2026-12-20**입니다.
- 상단에서 조회 월 선택 → **✎ 기간 설정** → 시작일·종료일 지정 → 저장합니다. 예: 2026-10-21 ~ 2026-11-19 또는 2026-11-20 ~ 2026-12-21도 직접 설정할 수 있습니다.
- **기간 중복 방지:** 특정 기간의 시작일을 바꾸면 직전 기간의 종료일이 같이 바뀌고, 종료일을 바꾸면 다음 기간의 시작일이 같이 바뀝니다. 날짜 사이에 구멍이 나거나 한 날짜가 두 기간에 중복 집계되지 않습니다. 기간 설정 창의 **자동 기준으로 되돌리기**로 변경을 취소할 수 있습니다.
- 날짜 설정은 `periodStarts`에 저장되어 GitHub 암호화 동기화·JSON 백업/복원에도 포함됩니다. **달력 월 · 1일 시작**을 선택하면 임의 기간 설정은 잠시 비활성화되고 1일~말일로 집계합니다. 다시 가계부 월로 돌아오면 사용자 지정 기간이 복구됩니다.
- 수입·변동지출·카드·계좌 예산·세부 지출 내역·대시보드의 집계가 기간에 맞춰 갱신됩니다. 고정지출의 자동 이월 날짜는 기존과 같은 날짜를 우선하되 새 기간 밖이면 해당 기간의 처음/마지막 날로 보정합니다. 기존 입력 기록 자체의 원본 날짜는 변경하지 않습니다.
- 엑셀 가져오기에서 날짜가 빈 줄은 이제 **선택한 가계부 기간의 실제 시작일**이 적용됩니다.

### 카드·계좌 예산 이체
- **카드·계좌 예산 → ＋ 계좌 간 이체** 또는 계좌 줄의 **이체**를 선택해, 보내는 계좌·받는 계좌·금액을 입력합니다. 받는 계좌가 아직 예산에 없어도 이름을 직접 입력할 수 있습니다.
- 표시 열은 **배정 예산 / 출장비·부수입·이월 / 이체(옮기기) / 이체 후 예산 / 이번 달 사용 / 이월·기타 지출 / 잔여 예산** 순서입니다.
- 예: 국민 배정 예산 **750,000원** 중 온통대전에 **200,000원** 이체 → 국민의 배정 예산 **750,000원** 그대로, 이체 **−200,000원**, 이체 후 예산 **550,000원**, 잔여 예산은 **550,000원 − 이번 달 사용 − 이월·기타**. 온통대전은 이체 **+200,000원**으로 표시됩니다.
- 계좌 간 이체는 **현재 선택한 기간에만 적용**되며, 월급·부수입·지출로 계산되지 않습니다. 실제 은행 송금을 수행하지 않으며 가계부 내부 예산의 수동 이동 기록만 남깁니다. 이체 기록은 화면 아래에서 수정·삭제할 수 있습니다. `budgetTransfers`에 저장되어 백업·암호화 동기화됩니다.
- 기존 **부수입 옮기기(계좌 기타 → 다른 계좌)** 기능은 별도 유지합니다.

### 글씨 확대
- 본문·메뉴·표·지출 내역·보조 설명·모달 입력 폼 글씨를 전반적으로 확대하고, 모바일에서도 표가 가로로 스크롤되도록 유지합니다.

## 계산
기본 집계 기간은 매월 21일(주말인 경우 직전 금요일)~다음 기간 시작 전날이며, 각 기간을 직접 지정하거나 달력 월 보기로 바꿀 수 있습니다.
실지출 = 결제 금액 − 할인 및 엔빵.
계좌별 이번 달 사용은 이월·기타 분류를 빼고, 이월·기타는 해당 분류 거래를 합산합니다.
잔여 예산 = 배정 예산 + 해당 계좌의 급여 외 수입(이월 포함) + 계좌 간 이체 순증감 + 기존 기타 부수입 옮기기 순증감 − 이번 달 사용 − 이월·기타 지출. 전월 잔액은 자동 승계하지 않으며, 직접 기록한 이월 수입만 반영합니다.
**그래프(월별 지출 흐름, 지출 비중)는 변동지출만** 보여 줍니다. 고정지출(적금·주식·모임 등)은 전부 제외하고, 변동지출 중 `적금` 분류도 제외합니다. 금액 카드와 표에는 고정지출이 그대로 포함됩니다.

고정지출은 분류 기준으로 **모임 / 적금 / 주식**으로 나눠 보여 줍니다(대시보드 금액 카드·월간 현황표·연간 표, 고정지출 화면). 셋 외의 분류가 있으면 "그 외"로 따로 표시합니다.

## 매월 자동 적용 (고정지출, 카드·계좌 예산)
- 한 번 입력해 두면 다음 달부터 **같은 내용이 자동으로 적용**됩니다. 고정지출은 이번 달까지만 채워지고, 아직 오지 않은 달은 그 달이 되면 채워집니다.
- 어떤 달에서 수정·삭제·추가하면 **그 달부터** 바뀐 내용이 적용되고 다음 달에도 이어집니다. 이전 달은 바뀌지 않습니다.
- 자동 적용된 고정지출에는 날짜 옆에 ↻ 표시가 붙습니다.
- 예산은 입력한 달부터 **뒤로만** 이어집니다. 그보다 앞선 달(예: 10월에 처음 입력했는데 9월을 볼 때)에는 **○월 예산 그대로 가져오기** 버튼이 나오고, 누르면 그 달에도 같은 예산이 생겨 수정할 수 있습니다. 수입만 연결된 계좌 줄의 **예산 추가**로 바로 만들 수도 있습니다.

## 세부 지출 내역 · 변동지출 예산 비교
- 예산 기본값은 **데이트 20만원 · 교통 20만원 · 생활비 30만원 · 통신비 5만원 · 운동 15만원 · 회사 25만원 · 그 외 15만원**, 총 **130만원**입니다.
- **✎ 예산 편집**을 눌러 7개 금액을 직접 변경할 수 있습니다. 편집한 값은 선택한 가계부 기간부터 다음 기간으로 이어지며 이전 기간은 바뀌지 않습니다. 카드·계좌별 예산과는 **별도로 관리**합니다.
- 변동지출 기록의 **실지출 = 결제 금액 − 할인 및 엔빵**을 자동으로 합산하고, 분류별 **예산 / 실제 지출 / 남은 금액 / 사용률 / 상태**를 한눈에 비교합니다. 고정지출은 제외하며 변동지출의 계좌 구분이 ‘기타’인 거래도 합산합니다. 금액이 NA인 건은 0원으로 계산합니다.
- 분류 연결 규칙: 변동지출의 `데이트` 또는 이전 버전에서 저장한 `데이터` → **데이트**; `생활` / `생활비` → **생활비**, 그중 세부 내역이 운동·헬스·필라테스·요가·수영이면 **운동**; `통신` / `통신비` → **통신비**; `교통` / `회사` / `운동`은 같은 이름으로; 나머지(미입력 포함)는 **그 외**.
- **분류 / 상태(초과·주의·여유·미사용) / 정렬(예산 항목 순·지출 많은 순·잔여 예산 적은 순·사용률 높은 순) / 세부 내역 검색**으로 필터링할 수 있습니다. 필터는 보이는 항목·거래만 바꾸며 전체 요약 금액은 해당 기간 전체 기준입니다.
- 7개 항목은 **접힌 토글**로 표시됩니다. 항목을 클릭하면 세부 항목별 합계 칩과 날짜·세부 내역·비고·카드/계좌·실지출 표가 펼쳐집니다. 펼친 표에서 변동지출을 수정하거나 추가할 수 있고, 모두 펼치기/접기도 가능합니다.
- 이전 버전에서 `데이터`라는 이름으로 수정·저장한 월별 예산도 **데이트 예산으로 자동 표시**됩니다. 기존 예산 금액과 거래 데이터는 유지합니다.
- 이전 버전의 `categoryBudgets` 데이터는 **삭제하거나 덮어쓰지 않고** 백업 호환용으로 유지됩니다. 새 예산은 `spendingBudgets`에 저장되며 암호화 동기화·백업에도 포함됩니다.

## 수입과 카드·계좌 예산
- 월급(구분 **급여**)은 입금 계좌(예: 농협)로 수입에 기록하고, **카드·계좌 예산**에서 국민 · CMA · 농협 등으로 나눠 배정합니다. 월급 자체는 입금 계좌의 잔여 예산에 중복으로 더해지지 않습니다.
- 카드·계좌 예산 화면 위쪽에 **이번 달 수입 · 계좌 예산 배정 · 고정지출(모임·적금·주식) · 남는 금액(용돈)**이 표시됩니다. 남는 금액 = 배분용 수입 − 계좌 예산 배정 − 고정지출이고, 모자라면 **부족한 금액**으로 바뀝니다. 급여 외 수입 중 입금 계좌가 지정된 기록은 배분용 수입에서 빠져 각 계좌의 예산에 한 번만 반영됩니다.
- **이월·출장비·부수입·이자·환급 등 급여 외 수입**을 기록할 때 수입 관리의 **계좌**에 실제 계좌(예: 온통대전)를 입력하면 카드·계좌 예산의 **그 계좌 '출장비·부수입·이월'** 칸에 더해집니다. 구분이 **급여**라면 계좌를 지정해도 배분용 수입에 남습니다. 계좌를 비워 둔 수입도 배분용 수입에 남습니다.
- 예: 수입 관리에 `2026-11-20 / 이월 / 온통대전 / 10,166원`을 기록하면 온통대전 예산의 **출장비·부수입·이월 +10,166원**으로 표시됩니다. 해당 계좌에 원래 배정한 예산·계좌 간 이체·지출도 함께 반영됩니다.
- **자동 이월은 하지 않습니다.** 이월 금액을 직접 수입 관리에서 기록하세요. 이미 예산 이체나 다른 기록으로 반영한 돈은 중복 기록하지 마세요.
- 이전과 같이 **기타** 계좌에 기록한 수입은 그대로 기타 계좌에 반영되며, 기존 **부수입 옮기기** 기능도 유지합니다. 이를 사용한 지출은 변동지출의 계좌 구분을 기타로 기록할 수 있습니다.

## 엑셀 가져오기 (복사·붙여넣기 / 파일)
- 변동지출 · 고정지출 · 수입 관리 화면의 내역 표 오른쪽 위 **📋 엑셀 가져오기**를 누릅니다.
- 엑셀에서 표를 **제목 줄까지 포함해** 복사해 붙여넣거나, 엑셀 파일(.xlsx)·CSV를 고릅니다. 시트가 여러 개면 보고 있는 달(예: "8월") 시트를 먼저 고릅니다.
- 제목 줄(날짜, 구분, 지출 내역, 결제 금액, 할인 및 엔빵, 실지출, 카드, 계좌, 비고 등)을 보고 **열을 자동으로 맞추고**, 미리 보기에서 바꿀 수 있습니다.
- ₩, 쉼표, 엑셀 회계 서식의 `-`(0원)를 알아서 읽습니다. 날짜가 빈 줄은 선택한 달의 시작일로 넣고, 연도 없는 날짜(8/22)는 보고 있는 달 기준으로 연도를 붙입니다. 결제 금액이 빈 변동지출은 NA로 들어갑니다.
- 합계 줄은 건너뛰고, **이미 있는 같은 기록도 건너뜁니다**(같은 표를 두 번 붙여넣어도 중복되지 않음). 읽지 못한 줄은 몇 번째 줄인지 알려 줍니다.
- .xlsx 파일을 열 때만 SheetJS(jsDelivr)를 불러옵니다. 인터넷이 안 되면 복사·붙여넣기를 쓰면 됩니다.

## 대시보드 · 이번 달 한눈에
- 월간 보기에서 예전 월간 현황표 대신 **이번 달 한눈에** 패널이 나옵니다(연간 보기에는 연간 현황표).
- **💡 한 줄 조언**: 세부 지출 내역의 7개 예산 대비 사용률과 기간 경과를 보고 *초과한 분류 · 속도가 빠른 분류 · 여유 있는 분류 · 마이너스 계좌 · 수입보다 많은 배정*을 한 줄로 알려 줍니다. 색으로 상태가 구분됩니다(초록 좋음, 노랑 주의, 주황 초과).
- **분류별 예산 사용** 막대: 새 7개 변동지출 분류와 예산을 기준으로 초과 → 주의 → 적정 → 여유 순으로 표시하고, 세로선은 지금까지 지난 기간을 뜻합니다.
- **계좌별 잔액** 막대와 **남는 금액 · 용돈**.
- **📝 특이사항 메모**: 달마다 메모를 남길 수 있습니다. 새 가계부 기간이 시작되면 **지난달 돌아보기**(변동지출, 평소 대비, 가장 많이 쓴 분류, 예산 초과 분류)가 자동으로 함께 나와서, 그걸 보며 이번 달 메모를 쓰면 됩니다.
- **월별 지출 흐름**의 색(분류)을 누르면 그 달 그 분류의 금액 · 비중 · 건수 · 세부 내역별 금액이 아래에 나옵니다. 다시 누르거나 ✕로 닫습니다.

## 그래프 색
- 대시보드 **월별 지출 흐름**은 막대를 **분류별 색으로 쌓아서** 보여 줍니다(마우스를 올리면 분류별 금액).
- 분류 색은 전체 기록에서 많이 쓴 순서로 정해져서, **어느 달·어느 그래프에서도 같은 분류는 같은 색**입니다.
## 변동지출 내역 필터
검색, 분류 외에 **카드 · 계좌 · 날짜 범위 · 실지출 금액 범위 · 정렬**(최신순, 오래된순, 실지출 큰 순/작은 순)로 걸러 볼 수 있습니다. 카드·계좌가 비어 있는 기록은 "카드 NA", "계좌 NA"로 골라 볼 수 있고, **필터 초기화**로 한 번에 풀 수 있습니다. 위쪽 "현재 조회 합계" 카드는 걸러진 기록의 합계입니다.

## 변동지출 NA(미입력)
- 날짜 외의 칸은 비워 둔 채 저장할 수 있고, 빈칸은 **NA**로 표시됩니다. 금액이 NA인 기록은 0원으로 계산됩니다.
- 변동지출 화면의 **NA 기록만 보기**로 모아 보고, **수정**으로 나중에 채우면 됩니다.

## 업데이트할 때
- 바뀐 파일만 올리다 보면 예전 파일이 섞일 수 있어요. 가장 안전한 방법은 **config.js를 뺀 모든 파일을 한 번에** 올리는 것입니다(같은 이름은 덮어써짐).
- 화면 맨 아래에 **버전**이 표시되고, `core.js`·`importer.js`가 `app.js`와 버전이 다르면 화면 위에 경고가 나옵니다.

## 파일 구성
- `index.html`, `style.css`, `app.js`, `core.js`, `merge.js`: 화면과 계산 (기존과 같음)
- `github-sync.js`: 잠금 화면, 암호화 저장, 기기 간 동기화
- `importer.js`: 엑셀 복사·붙여넣기 / 파일 가져오기
- `device.js`: 기기 등록과 PIN 4자리 (5번 틀리면 등록 삭제)
- `vault.js`: 암호화 도구 (PBKDF2-SHA256 60만 회 → AES-GCM 256)
- `setup.html`, `setup.js`: 처음 설정, 토큰·비밀번호 변경
- `config.js`: 비밀번호로 잠긴 설정 (setup.html이 만들어 줌)
- `tests/`: 계산·병합 테스트, 업데이트 화면/기능 테스트(`node tests/app-features.test.cjs`), 전체 흐름 테스트(`node tests/e2e.test.mjs`) · 마지막 테스트는 `npm i jsdom@24 fake-indexeddb@6` 필요

> 배포 시에는 **UPDATE_GUIDE.md**도 확인하세요. 현재 사이트의 `config.js`를 덮어쓰지 않도록 배포용 압축 파일에는 설정 파일을 제외합니다.
